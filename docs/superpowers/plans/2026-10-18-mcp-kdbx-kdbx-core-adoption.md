# mcp-kdbx adopts kdbx-core and the rebuilt diff-kdbx: implementation plan

Spec: `~/github/kdbx/kdbx-core/docs/superpowers/specs/2026-10-18-kdbx-core-design.md`, section 5 ("mcp-kdbx") and section 9 (implementation decisions, which win where they differ). The mcp-kdbx v0.1 spec (`docs/superpowers/specs/2026-05-08-mcp-kdbx-design.md`) stays canonical for the protocol surface, auth, semantics, audit and threat model; this work updates its implementation notes and the audit format where stated below.

Prerequisites: kdbx-core 0.1 settled (done); diff-kdbx rebuilt on kdbx-core and merged to its `main` (the sibling checkout `../diff-kdbx` must be on that `main`).

## Goal

mcp-kdbx stops carrying its own copies of the ecosystem rules (path grammar, visibility, TOTP, field names) and its stage diff uses diff-kdbx's snapshot API, so its keepass version is no longer tied to diff-kdbx's. Audit hashes become keyed fingerprints, closing the low-entropy oracle (a reviewer recovered a fixture PIN from the current `sha256` in under 10,000 tries).

## Ground rules

- Branch `adopt/kdbx-core` from `main`. Dependencies: `kdbx-core = { path = "../kdbx-core", features = ["keepass-0_12"] }` (default features keep `kdf`), `diff-kdbx = { path = "../diff-kdbx" }` (library only, no `cli`). Switching both to crates.io versions happens at publish time, not in this plan.
- All mcp-kdbx invariants in CLAUDE.md hold throughout. Every error code and tool surface stays as is unless a task below changes it, and the conformance suite pins any change.
- Test-first; one conventional commit per task with the session trailers; no em-dash characters; gates: `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all-features`, `bash scripts/ci-audit.sh`.

## Tasks

1. **Rename the internal module.** `src/kdbx_core/` becomes `src/engine/` (a crate-root module named `kdbx_core` would be ambiguous with the external `kdbx_core` crate in `use` paths). Mechanical; no behavior change; update `ci-audit.sh` paths and docs. Commit.
2. **Dependencies.** Add kdbx-core and point diff-kdbx at the rebuilt crate; adjust the stage-diff call site minimally so the crate builds (full migration is task 6). Commit.
3. **Paths.** Replace `engine::path` with `kdbx_core::path`: resolve by capturing a `Snapshot` (or reusing one cached per vault generation, invalidated on every stage mutation, save, lock and unlock) and mapping the resolved UUID to the live keepass record. Use `PathIndex` for every listing (never per-node `path_of`). Map `PathError` to `PATH_INVALID` and `ResolveError` to the existing not-found codes. Group paths now format with a trailing `/` (accepted decision); update conformance expectations deliberately. Keep `address.rs` uuid addressing. Delete `engine/path.rs` once nothing uses it; port any mcp-specific path tests that kdbx-core's suite does not already cover. Commit.
4. **Visibility and fields.** Replace `engine::visibility` with `kdbx_core::visibility` (`is_secret`, `metadata_value`). Behavior change: a Password whose protection flag is off is now hidden from bulk reads and search (the one secret predicate); add a test. Replace field-name literals with `kdbx_core::fields`. Commit.
5. **TOTP.** Replace `engine::totp` with `kdbx_core::otp` (`capture::keepass_0_12::otp_fields` then `otp::resolve_fields`; `code_at(now)`). `has_otp` is true only for a configuration that resolves; a malformed configuration returns a typed error from `kdbx_get_otp` (add an `OTP_INVALID` code with the `MalformedReason` in details, and pin it in conformance) instead of looking like "no OTP". Steam codes are supported. Commit.
6. **Stage diff on the snapshot API.** `kdbx_diff_pending` captures canonical and working with one random `FingerprintKey` per call (32 bytes from the OS RNG) under `Sealing::Fingerprint` and calls `diff_kdbx::compute`. Map the new `ChangeSet` (one record per node, `moved_from`, property changes) onto the existing response shape, or extend the shape where the new information is useful (document in the spec notes); fingerprints never reach the agent (they are meaningless across calls with a random key). Wildcard arms for `#[non_exhaustive]` enums. Port the redaction tests, and add the reviewer's case: a protected UserName and a protected custom field that change appear as "modified" with no value. Commit.
7. **Keyed audit fingerprints.** At unlock, derive one `FingerprintKey` per session with `FingerprintKey::derive(KeyMaterial { password, keyfile bytes }, root_uuid, DeriveParams::for_header(...))`, inside `block_in_place` like the KDF, and drop it on lock. Reveal events carry `fingerprint` (64 hex, `Domain::Field`) instead of `sha256`; `vault_unlocked` records the `DeriveParams` (its Display form) so a verifier can reproduce fingerprints. `kdbx_list_attachments` and `download_attachment` report a keyed `fingerprint` (`Domain::Attachment`) instead of a plain `sha256`. Remove `hash_revealed` and `REVEAL_DOMAIN_PREFIX`. Update the pinned JSONL format test deliberately, the spec's audit table, and `docs/operations.md` (including how to verify a logged fingerprint with `diff-kdbx fingerprint`). Add a test that the fixture PIN cannot be recovered from the log by hashing candidates without the key (i.e. the logged value differs from every unkeyed digest of it). Commit.
8. **Views from the snapshot (if it fits cleanly).** Build read views from the cached `Snapshot` (sealed values have no plaintext, so the views cannot leak by construction), keeping reveal tools on the live database. If this would destabilize the adapter, record it as a follow-up instead and say why. Commit.
9. **CI and docs.** Until kdbx-core and the new diff-kdbx are published, CI checks out `queelius/kdbx-core` and `queelius/diff-kdbx` as siblings (note: kdbx-core has no GitHub repo yet; the orchestrator creates it before mcp-kdbx is pushed). CLAUDE.md (architecture, test counts, the kdbx-core relationship), README, spec implementation notes. Commit.
